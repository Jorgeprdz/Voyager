# Registro público OAuth (sin secretos)

La APK predeterminada no contiene client IDs y no conecta cuentas. Las operaciones cloud están implementadas, pero requieren registro, consentimiento y validación real; sólo esos requisitos son `BLOCKED_EXTERNAL`.

Compilar con `-Pfinderdex.DRIVE_CLIENT_ID=<client ID Android propio>` y/o `-Pfinderdex.ONEDRIVE_CLIENT_ID=<application ID público propio>`; equivalentes de entorno: `FINDERDEX_DRIVE_CLIENT_ID` y `FINDERDEX_ONEDRIVE_CLIENT_ID`. Nunca pasar client secrets. Para Google, usar `-Pfinderdex.oauthScheme=<esquema autorizado para ese cliente>` (habitualmente esquema inverso del ID). La redirección exacta es `<esquema>:/callback`; registrar esa URI también en la aplicación pública Microsoft. Package de evaluación: `com.finderdex.preview`; registrar su certificado real, obtenido mediante `apksigner verify --print-certs` sobre la APK CI. El esquema por defecto no representa un registro Google válido.

Google debe tener Drive API habilitada, pantalla de consentimiento y usuarios de prueba/validación del scope Drive. Los esquemas personalizados Android están deshabilitados por defecto: habilitarlos sólo si el registro/organización lo admite; no sustituir un cliente Android por un secreto web ni eludir restricciones. Si esa opción no está disponible se requiere adaptar el registro a Google Identity Services (pendiente, no simulado). Microsoft: registro public/mobile client, cuentas admitidas y consentimiento delegado `Files.ReadWrite`, `offline_access`, `openid`; sin MSAL/broker (AppAuth OAuth PKCE).

AppAuth abre el navegador del sistema, genera state/verificador PKCE e intercambia código. `AuthState` renueva tokens; estado cifrado con Android Keystore y excluido de backup/transferencia. Desconectar elimina tokens locales; revocar el consentimiento remoto requiere hacerlo en el proveedor. Nunca se presenta una identidad/account email que no se haya consultado.

Validar con cuentas de prueba antes de publicar: consentimiento/cancelación, token caducado/revocado, navegación/páginas, archivos Workspace exportados, descarga cancelada (limpieza del documento incompleto), uploads pequeños/grandes, conflictos y desconexión. No se ha realizado este E2E externo.

Límites explícitos: sesión grande Graph reintenta chunks durante la operación, pero no persiste el stream/sesión para reanudar tras matar el proceso; copia asíncrona tiene monitor acotado y puede quedar pendiente en servidor al cancelar; confirmar destino antes de repetir. Drive resumable requiere tamaño conocido; no reintenta automáticamente una creación ambigua. Carpetas cloud no se copian recursivamente. Las operaciones cloud aún no se agregan al historial del coordinador local.

Referencias: [AppAuth Android](https://github.com/openid/AppAuth-Android), [configurar OAuth Google](https://support.google.com/googleapi/answer/6158849), [Drive uploads](https://developers.google.com/workspace/drive/api/guides/manage-uploads), [Graph upload sessions](https://learn.microsoft.com/graph/api/driveitem-createuploadsession), [Graph copy](https://learn.microsoft.com/graph/api/driveitem-copy).
