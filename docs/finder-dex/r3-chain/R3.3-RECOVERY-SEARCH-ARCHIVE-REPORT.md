## Implemented changes

### Journal and recovery behavior

`AndroidTransferHistoryStore` persists bounded results and checkpoints the single running operation. It never includes credentials or instructions to replay. An interrupted active marker is converted on the next app open to a failed/uncertain event requiring destination inspection. Completed/failed/cancelled results survive restart. The journal does **not** provide a durable executable queue, resumable byte offset, universal pause/resume/retry or true process-death continuation. Cloud uploads and network transfers are **not yet unified** under one recoverable pipeline. These require a provider-capability model, idempotent staged writes, conflict resolution and carefully tracked durable identities.

`FileOperationCoordinator.movePath` now checks byte contents by SHA-256 and checks copied folder structure recursively before deleting the source. If a remote copy cannot be reread, fails its hash or is cancelled, the source is retained. This entails additional I/O, especially on large remote files; atomicity against concurrent remote changes cannot be guaranteed by the abstract provider API.

### Search

`StorageCategoryIndex` uses existing cancellable progressive traversal, no symlink traversal and coverage statuses; `StorageSearchFilters` adds scoped root, recursion flag, type, size and modified time, combined at scan time. The UI exposes filters and 12 stored queries; search scope is denied when outside accessible shared storage. Existing `StorageSearchViewModel.validate` rejects stale files before opening. Current scope is **local shared storage**; remote/cloud indexing, a dedicated Finder Desktop advanced search surface, and exact display of all uncovered remote locations remain work items. Other-language labels temporarily fall back to English; Spanish and default labels exist.

### Archives and Android sharing

The manifest contains narrowly scoped archive MIME handlers for `ACTION_VIEW` with `content://`, and `ACTION_SEND` with `EXTRA_STREAM`. Nothing changes Android's default handler automatically. `ExternalArchiveActivity` reads temporary content grants, previews a bounded list and opens Android's SAF tree picker before extracting with `ArchiveService`. Preview caches ZIP temporarily (max 128 MiB), lists at most 250 entries, TAR preview scan budget 256 MiB, and deletes its temporary ZIP. External extraction adds a 25,000-entry / 2 GiB written-data budget. No silent replacement: existing extraction-root name causes an explicit conflict error; a refined conflict-picker flow is still pending.

RAR remains explicitly unsupported in the executable code. Research: `junrar/junrar` describes RAR up to v7, password and multipart handling (https://github.com/junrar/junrar), while older Android forks lack RAR5/password support; the pure Java library's Android 17 compatibility, licensing obligations and untrusted-archive safety must be validated before adding it. `7-Zip-JBinding` has native-platform distribution and licensing complications; Android ARM64 loadability is not established. Neither dependency was added without verification.
